# Database Design

PostgreSQL 16 with Flyway migrations in `db/migration/<module>/`, versioned by timestamp (`V20261112_0100__shared_infrastructure.sql`). **Implemented so far:** shared infrastructure and auth tables (Phase 2). Conventions:

- Primary keys are `id UUID` (generated by the app as UUIDv7, so they sort by time).
- Business IDs that are visible externally (`AUD10001`, `JRN10001`) are stored in `*_key` columns and are unique within a tenant.
- Every tenant-owned table has `tenant_id UUID NOT NULL REFERENCES tenants(id)`. Composite indexes start with `tenant_id`.
- `created_at`, `updated_at` are `timestamptz`. Optimistic locking uses a `version BIGINT`.
- JSONB is used only where the shape is genuinely dynamic: audience content, journey graph and node config, event payloads, template variables, provider config.
- **Destructive changes** (drops, type narrowing) require approval and go through an expand/contract pattern.

## Tables

### Identity and tenancy
```
tenants(id, key UNIQUE, name, status, settings JSONB, created_at)
applications(id, tenant_id FK, name, api_key_hash UNIQUE, api_key_prefix, scopes TEXT[],
             rate_limit_per_min, status, created_at, last_used_at)
users(id, tenant_id FK, email, password_hash (bcrypt), display_name, roles TEXT[], status, last_login_at)
      UNIQUE(tenant_id, email)
```

### Audience
```
audiences(id, tenant_id, audience_key, name, status[DRAFT|ACTIVE|INACTIVE|ARCHIVED],
          current_version INT, created_by, updated_by, created_at, updated_at)
  UNIQUE(tenant_id, audience_key); index(tenant_id, updated_at DESC); index(tenant_id, status)
audience_versions(id, tenant_id, audience_id FK, version INT, content JSONB NOT NULL,
          compiled_criteria JSONB NOT NULL, created_by, created_at) UNIQUE(audience_id, version)
  GIN index on content (jsonb_path_ops)
audience_key_counters(tenant_id PK, next_value BIGINT)   -- AUD10001, AUD10002, … per tenant
```
Implemented in Phase 3 (`db/migration/audience/V20261113_0300__audience.sql`). Versions are immutable. ARCHIVED is the soft delete.
`content` holds the free-form criteria from the spec. `compiled_criteria` is the normalized rule tree that the evaluator uses (see JOURNEY_ENGINE_DESIGN §Audience).

### Customer
```
customers(id, tenant_id, customer_key, email, phone_e164, first_name, last_name,
          attributes JSONB, status, created_at, updated_at) UNIQUE(tenant_id, customer_key)
  GIN index on attributes
customer_attributes(customer_id FK, name, value_text, value_num, value_ts, updated_at)
  PK(customer_id, name); index(tenant via customer, name, value_text)
  -- typed projection of hot attributes for indexed segmentation; JSONB stays the source
customer_devices(id, customer_id FK, platform[IOS|ANDROID|WEB], token UNIQUE, status, last_seen_at)
customer_preferences(customer_id FK, channel[SMS|PUSH|APP_INBOX], consent[OPT_IN|OPT_OUT|UNKNOWN],
          consent_source, consent_at, quiet_hours JSONB, frequency_cap JSONB)
  PK(customer_id, channel)
```

### Events
```
event_schemas(id, tenant_id, event_name, version, json_schema JSONB, status)
  UNIQUE(tenant_id, event_name, version)
incoming_events(id, tenant_id, event_id, idempotency_key, application_id FK, customer_id FK NULL,
          event_name, payload JSONB, occurred_at, received_at,
          status[RECEIVED|VALIDATED|PROCESSED|REJECTED|FAILED])
  UNIQUE(tenant_id, event_id); UNIQUE(tenant_id, idempotency_key) WHERE idempotency_key IS NOT NULL
  index(tenant_id, customer_id, occurred_at DESC); index(tenant_id, event_name, occurred_at DESC)
event_processing_logs(id, incoming_event_id FK, stage, outcome, detail JSONB, created_at)
```
`incoming_events` is a candidate for monthly range partitioning on `received_at` once volume justifies it.

### Journeys
```
journeys(id, tenant_id, journey_key, name, description, status[DRAFT|ACTIVE|PAUSED|ARCHIVED],
         published_version_id FK NULL, draft_graph JSONB, reentry_policy JSONB, ...)
  UNIQUE(tenant_id, journey_key)
journey_versions(id, journey_id FK, version INT, definition JSONB NOT NULL, checksum,
         trigger_type, trigger_event_name, published_at, published_by)
  UNIQUE(journey_id, version); index(tenant via journey, trigger_event_name)
journey_nodes(id, journey_version_id FK, node_key, type, config JSONB, position JSONB)
  UNIQUE(journey_version_id, node_key)
journey_connections(id, journey_version_id FK, source_node_key, target_node_key, branch_label NULL)
  FK (journey_version_id, source_node_key) -> journey_nodes; same for target
```
`journey_versions.definition` is the immutable, authoritative copy of the graph. `journey_nodes` and `journey_connections` are normalized projections written once at publish time, used for reporting, analytics joins and FK integrity. Drafts live in `journeys.draft_graph` until they are published.

### Execution
```
journey_executions(id, tenant_id, request_id, journey_id FK, journey_version_id FK, customer_id FK,
         trigger_event_id FK NULL, status[PENDING|RUNNING|WAITING|PAUSED|COMPLETED|FAILED|CANCELLED],
         context JSONB, current_node_keys TEXT[], started_at, completed_at, error JSONB, version)
  UNIQUE(tenant_id, request_id)
  index(tenant_id, journey_id, status); index(customer_id, journey_id, started_at DESC)
journey_execution_steps(id, execution_id FK, node_key, node_type, attempt INT,
         status[PENDING|RUNNING|SUCCEEDED|FAILED|SKIPPED|WAITING], input JSONB, output JSONB,
         error JSONB, started_at, finished_at)
  UNIQUE(execution_id, node_key, attempt)   -- step-level idempotency
```

### Templates and notifications
```
templates(id, tenant_id, template_key, channel, version, subject, body, variables_schema JSONB,
          locale, status)  UNIQUE(tenant_id, template_key, version)
notification_requests(id, tenant_id, request_id, customer_id FK, channel, template_id FK,
          template_version, variables JSONB, rendered JSONB, metadata JSONB,
          execution_id FK NULL, step_id FK NULL,
          status[ACCEPTED|SUPPRESSED|QUEUED|SUBMITTED_TO_NM|SENT|OPENED|FAILED],
          suppression_reason, correlation_id (NM nmRequestId), adapter_key,
          external_message_id (nmSmsId | fcmMessageId | msMessageId), attempts, created_at, updated_at)
  UNIQUE(tenant_id, request_id); index(customer_id, created_at DESC); index(status, updated_at)
notification_delivery_logs(id, notification_id FK, status, provider_response JSONB, created_at)
-- inbox_messages removed (D15): App Inbox content and read state are stored in the MS APIs
provider_configurations(id, tenant_id, channel, provider_key, priority, config_encrypted BYTEA,
          status)  UNIQUE(tenant_id, channel, provider_key)
```

### Platform infrastructure
```
outbox_events(id, tenant_id, aggregate_type, aggregate_id, event_type, payload JSONB,
          created_at, published_at NULL)  partial index WHERE published_at IS NULL
jobs(id, tenant_id, queue, dedup_key UNIQUE NULL, payload JSONB, run_at, status
          [READY|LEASED|DONE|DEAD], attempts, max_attempts, lease_token, lease_until, last_error,
          created_at, updated_at, completed_at)
  CHECK (status = 'LEASED') = (lease_token IS NOT NULL)
  partial indexes: (queue, run_at) WHERE READY · (queue, lease_until) WHERE LEASED · (tenant_id, updated_at) WHERE DEAD
idempotency_keys(tenant_id, scope, idem_key, request_hash, response JSONB, created_at)
  PK(tenant_id, scope, idem_key)  -- TTL cleanup job (Phase 12)
audit_logs(id, tenant_id, actor_type, actor_id, action, entity_type, entity_id,
          before JSONB, after JSONB, ip, created_at)  index(tenant_id, entity_type, entity_id)
```
